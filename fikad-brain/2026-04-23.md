⏺ Here's what I found:                                                                      
                                                                                        
  ★ Insight ─────────────────────────────────────                     
  OTEL 401 Diagnosis — the error is clear and the fix is straightforward.                   
                                                                                            
  1. What's happening: The OpenTelemetry OTLP span exporter on the Celery worker is failing 
  to authenticate with Grafana Cloud. It retries every ~5 seconds, flooding logs with Failed
   to export span batch code: 401, reason: Unauthorized from both ForkPoolWorker-1 and      
  ForkPoolWorker-2.                                                                         
  2. Scope: This is worker-only — the API service (thumbforge-api) doesn't show any OTEL 401
   errors (its 401s are normal auth failures from unauthenticated API requests). The API    
  service likely either has correct credentials or doesn't have OTEL enabled.               
  3. Duration: It's been happening since at least April 22 at 05:00 UTC (over 29 hours of
  continuous spam).
  ─────────────────────────────────────────────────

  Root cause: The OTEL_EXPORTER_OTLP_HEADERS env var on the hooksnap-celery-worker service
  has expired or misconfigured Grafana Cloud Basic auth credentials. The OTEL setup in
  backend/app/utils/otel.py reads this header for OTLP/HTTP export.

  Impact:
  - No traces are being exported from the worker to Grafana Cloud (tracing is blind)
  - The retry loop adds noise to logs (every 5s × 2 workers = ~24 errors/minute)
  - No impact on thumbnail generation itself — OTEL failures are non-blocking

  Fix options (pick one):

  1. Update credentials: Go to Render → hooksnap-celery-worker → Environment → update
  OTEL_EXPORTER_OTLP_HEADERS with fresh Grafana Cloud credentials (generate a new API token
  in Grafana Cloud → grafana.com → My Account → API Keys or Stacks → your stack → OTLP
  config)
  2. Disable OTEL on worker (if you're not using Grafana tracing right now): Set
  OTEL_ENABLED=false on the hooksnap-celery-worker service. This silences the exporter
  completely via the kill switch in otel.py.
  3. Also check thumbforge-api: Verify whether OTEL_EXPORTER_OTLP_HEADERS is set on the API
  service too — if the same credentials are shared, they may also be expired but the API
  service might not be logging the error as visibly.

  Would you like me to disable OTEL on the worker via OTEL_ENABLED=false to stop the log
  spam, or do you want to update the Grafana credentials instead?
