#### rtk의 내부 동작
- 기본적으로 standard cli output 들은 인간을 위한 것. rtk는 llm을 위해, 인간을 위한 불필요한 정보들을 제거한다.

rtk 흐름
- claude는 tool use를 발도한다. `Bash({ command: "git status" })`
- `PreToolUse` hook에서, bash command가 호출되면 rtk 커맨드로 감싼다.
- os는 `rtk git status` 를 호출한다.
- rtk는 필터를 적용해 strips ansi, dedups, summarizes counts 등의 작업을 처리한다.
- tool result를 반환해, token 사용을 절약한다.
- 즉 `PreToolUse` 를 wrapping 하려면, tool을 호출하는 방법을 알아야 한다.
- **claude의 reasoning token도 아끼게 된다.** `git status` output을 읽게 되면, thinking-mode token을 쓰게 된다. 하지만 rtk에 의해 pre-filtered output을 얻으면 parsing이 엄청 가벼워진다.

#### semantic compression
- `PostToolUse` hook이 불렸을 때, haiku로 summarization 을 돌리되, facts 들은 그대로 넣어서 리턴하기.
```
PostToolUse: receives tool_result JSON on stdin
	if len(result) > 10KB:
		call Claude Haiku: "summarize this tool output, preserve facts"
		return summary on stdout
	else:
		pass through unchanged
```


#### context window basics
- 다음 형태로 context window가 만들어짐. 그리고 이 structure는 api request에 그대로 전달됨.
```
system_prompt: tools, env, CLAUDE.md, rules, ...
cached_prefix: replayed conversation up to last cache breakpoint
recent_messages: messages since last cache breakpoint
new_user_message: your prompt
```

- prompt cache는 cached prefix에 대해서 비용을 줄여주기는 하지만, `token budget consumed` 는 줄여주지 않는다. 
	- 즉 비용 절감과 token limit 절감은 다른 이야기.
- compaction  이후 cli는 in-memory conversation을 `[system] + [summary] + [last N messages]` 로 갈아치운다.
- 이후 compation event가 jsonl에 추가된다. `{"type": "compaction","summary":"..."}`
- logical work units 사이에 compaction 보다, mid-investigation 사이의 compaction에서 주요 정보를 잃을 가능성이 높다. 따라서 process rotation이 mid-session compaction보다 낫다.
	- Q. tick을 N 번 지정해서, N 번 이후에 프로세스를 다시 재시작하는 방법도 있을까.

#### hook behavior
- hook은 같은 이벤트에 대해서 array로 순서대로 등록할 수 있고, 앞에 선언된 것들부터 수행된다. 이전 hook의 stdout을 stdin으로 받게 된다.
- `settings.json` 은 scope에 걸쳐서 merge된다. `~/.claude/settings.json` -> `<repo>/.claude/settings.json` -> `<repo>/.claude/settings.local.json`
- project setting은 user setting을 override 한다.
- `PreToolUse` blocking은 괜찮지만, `PostToolUse` blocking은 이상하다.
- `{"decision":"block","reason":"..."}` 같은 형태로 claude와 통신할 수 있다.
- python보다는 go/rust binary가 hook에서 돌릴 코드로 적합하다. 바이너리가 훨씬 빠르다.
